```text
CREATED ──confirm──► PENDING ──success──► SUCCESS
   │                    │
   │                    ├──decline──► DECLINED
   │                    │
   │                    └──timeout──► PENDING (retry)
   │
   └──cancel──► CANCELED
```

## B. Таблицы

### B.1. Правила валидации

| ID  | Условие                                              | Действие / код / HTTP                             | Обоснование                                      |
| --- | ---------------------------------------------------- | ------------------------------------------------- | ------------------------------------------------ |
| V-1 | Обязательное поле пустое                             | Отклонить; VALIDATION_ERROR; 422                  | Неполные данные вызывают ошибки обработки.       |
| V-2 | order_id не соответствует `^[A-Za-z0-9_-]{1,64}$`    | INVALID_FORMAT; 422                               | Единый формат упрощает поиск и сопоставление.    |
| V-3 | amount ≤ 0 или > 1 000 000                           | AMOUNT_OUT_OF_RANGE; 422                          | Исключает недопустимые суммы и финансовые риски. |
| V-4 | currency не RUB                                      | UNSUPPORTED_CURRENCY; 422                         | Поддерживается только RUB.                       |
| V-5 | recipient отсутствует или INACTIVE                   | RECIPIENT_NOT_FOUND; 404                          | Платёж не направляется неактивному получателю.   |
| V-6 | purpose > 200 символов или содержит PAN (13–19 цифр) | INVALID_PURPOSE; 422                              | Защита от утечки реквизитов и переполнения поля. |
| V-7 | amount имеет > 2 знаков после точки                  | INVALID_AMOUNT_PRECISION; 422                     | Предотвращает ошибки округления.                 |
| V-8 | order_id + recipient уже существуют                  | DUPLICATE_ORDER; 409                              | Не допускает повторный платёж по заказу.         |
| V-9 | Повтор Idempotency-Key                               | DUPLICATE_REQUEST; 200, вернуть сохранённый ответ | Не создаёт новую операцию при повторе.           |

### B.2. Матрица ошибок

| Ситуация | Код | HTTP | Retryable |
|---|---|---:|---|
| Обязательное поле пустое | VALIDATION_ERROR | 422 | нет |
| order_id не по regex | INVALID_FORMAT | 422 | нет |
| Сумма вне диапазона | AMOUNT_OUT_OF_RANGE | 422 | нет |
| Валюта не RUB | UNSUPPORTED_CURRENCY | 422 | нет |
| Получатель отсутствует/INACTIVE | RECIPIENT_NOT_FOUND | 404 | нет |
| Некорректное назначение / PAN | INVALID_PURPOSE | 422 | нет |
| Точность суммы > 2 знаков | INVALID_AMOUNT_PRECISION | 422 | нет |
| Дубликат пары order_id + recipient | DUPLICATE_ORDER | 409 | нет |
| Повтор того же Idempotency-Key | DUPLICATE_REQUEST | 200 | нет (повтор безопасен) |
| Отказ шлюза: недостаточно средств | INSUFFICIENT_FUNDS | 402 | нет |
| Отказ шлюза: карта отклонена | CARD_DECLINED | 402 | нет |
| Истёк токен | код требует сверки; OpenAPI предусматривает 410 | 410 | нет |
| Таймаут шлюза | TIMEOUT | 504 | да, только с тем же ключом |
| Платёж не найден | код требует сверки | 404 | нет |
| Отмена конечного платежа | код требует сверки | 409 | нет |

Коды для истёкшего токена, отсутствующего платежа и невозможной отмены необходимо сверить с кодом прототипа: тесты Case1 их отдельно не фиксируют.

| **T1-9** | Неактивный получатель                    | recipient существует, статус INACTIVE                         | HTTP 404; RECIPIENT_NOT_FOUND; запись не создаётся      | HTTP 404; RECIPIENT_NOT_FOUND; сообщение `Recipient not found or inactive.`; число платежей не изменилось (12) | PASS |
